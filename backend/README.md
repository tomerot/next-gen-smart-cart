# Backend

The central server of the system. Provides the business logic and stores data in a MongoDB database. Built with FastAPI.

The backend consists of two parts:

- **API Server**: each request goes through a **router** (the endpoint), which calls a **service** (the business logic), which reads and writes **models** (MongoDB documents through Beanie). **Schemas** validate the request and response bodies, and **clients** wrap the external APIs: Google Gemini for product recommendations and Twilio for SMS login codes.
- **Maintenance Tools** (`maintenance/`): standalone scripts, executed manually and offline whenever the store layout changes. They precompute data that would be too expensive to calculate on every request and save it to a file, which is committed and deployed together with the API Server and loaded at runtime.

## Structure

```
backend/
├── main.py                    # Entry point
├── database.py                # MongoDB connection
├── routers/                   # Endpoints
├── services/                  # Business logic
├── models/                    # MongoDB documents
├── schemas/                   # Request and response models
├── clients/                   # Gemini and Twilio clients
├── maintenance/               # Maintenance Tools
├── store_layout.json          # Store grid
├── grid_distance_matrix.json  # Walking distances, generated by the Maintenance Tools
├── requirements.txt
└── .env.example
```

| File | Purpose |
|---|---|
| `main.py` | Creates the app: connects to MongoDB, registers the models and routers, starts the Gemini and Twilio clients and sets CORS |
| `database.py` | MongoDB connection |
| `store_layout.json` | Store map: a 12 × 26 grid of aisles, shelves, cash registers and restrooms, plus the entrance |
| `grid_distance_matrix.json` | Walking distance between every pair of grid cells, generated by the Maintenance Tools. Lets the API Server build routes without searching for paths on every request |
| `requirements.txt` | Python dependencies |
| `.env.example` | Required environment variables: MongoDB, Gemini, Twilio and the numbers that receive a real SMS (`REAL_SMS_PHONES`) |

### `routers/`

| File | Prefix | Purpose |
|---|---|---|
| `users.py` | `/users` | Profile, status after login (saved cart, saved list), adding and removing allergies and dietary needs |
| `otp.py` | `/otp` | Sending and verifying SMS login codes. Twilio's free trial only delivers SMS to verified numbers, so only the numbers listed in `REAL_SMS_PHONES` receive a real code, and all other numbers log in with `000000` |
| `products.py` | `/products` | Search, scan with an allergy and diet check, alternatives, nutrition, ingredients, availability and location |
| `shopping_list.py` | `/shopping-list` | Saving, loading and deleting the shopping list with its route |
| `cart_session.py` | `/cart-session` | Backing up, restoring and deleting the cart |
| `checkout.py` | `/checkout` | Checkout and "you might need" suggestions |
| `vapi_webhook.py` | `/vapi-webhook` | The single endpoint VAPI calls for every tool the voice assistant uses (product info, nutrition, AI alternatives, allergy and diet updates). Routes each call to the matching service |

### `services/`

| File | Purpose |
|---|---|
| `user.py` | Creates users on first login, updates allergies and dietary needs, reports the user's status |
| `otp.py` | Generates codes, sends them by SMS and verifies them within 3 minutes |
| `product.py` | Checks products against the user's allergies and diet, finds safe alternatives in the same category, asks Gemini for alternatives that match a request such as "less sugar", and finds products by name |
| `shopping_list.py` | Saves shopping lists and computes their route from the category positions stored in MongoDB |
| `route_optimizer.py` | Builds the route of a shopping list: loads `grid_distance_matrix.json` into a NumPy array, extracts the distances between the list's category positions and orders them into the shortest path from the entrance with Google OR-Tools |
| `cart_session.py` | Saves, loads and deletes the cart backup |
| `product_purchase_tracking.py` | Updates each product's average days between purchases at checkout and finds the products that are due again |

### `models/`

| File | Document |
|---|---|
| `user.py` | User: phone, allergies, dietary needs, last checkout date |
| `product.py` | Product: barcode, name, company, category, price, size, image, ingredients, allergens, dietary tags, nutrition |
| `category.py` | Store category and its position on the grid |
| `shopping_list.py` | Shopping list: items, category order and route coordinates |
| `cart_session.py` | Cart backup and its last update time |
| `product_purchase_tracking.py` | Per user and product: number of purchases, last purchase date, average days between purchases |
| `otp.py` | Login code and its expiration time |

### `schemas/`

| File | Purpose |
|---|---|
| `user.py` | Profile, status, and allergy and diet requests |
| `product.py` | Product details, conflicts, alternatives, nutrition, location and availability |
| `product_item.py` | Product data stored in cart backups and shopping lists |
| `shopping_list.py` | Shopping list requests and responses |
| `cart_session.py` | Cart backup requests and responses |
| `purchase_tracking.py` | Checkout and suggestions |
| `otp.py` | Code verification request |

### `clients/`

| File | Purpose |
|---|---|
| `gemini_client.py` | Google Gemini client, created once at startup |
| `twilio_client.py` | Twilio SMS client, created once at startup |

### `maintenance/`

| File | Purpose |
|---|---|
| `calculate_grid_distances.py` | Computes the walking distance between every pair of cells in `store_layout.json` with BFS and writes `grid_distance_matrix.json`. Executed after every change to the store layout |
